## 2. 10 题盲评

盲评方法：评审只看到题干 + 出处摘录 + 题型定义，不看到模型声称的题型。

结果：题型 10/10、理解 10/10、业务视角 10/10、溯源 10/10，全部达到验收线。

### 1. 模型选型（盲评后标注：concept）

- 题干：在给客户做方案时，客户常问“你们为什么不用最聪明的模型”。请结合材料中关于指令模型和推理模型的描述，向客户解释：为什么不能所有任务都选推理模型？不用指令模型会带来什么业务问题？
- 出处：指令模型
      + 无思考过程    速度快 但是准确性一般  适合较简单性任务
    + 推理模型
      + 有思考过程    速度慢 但是准确性较高   适合较复杂性任务
- 参考答案：推理模型有思考过程、速度慢但准确性高，适合复杂任务；指令模型无思考过程、速度快但准确性一般，适合简单任务。若所有任务都用推理模型，简单创作类任务会因速度慢、成本高而影响用户体验和交付效率，且客户为不需要的准确性买单。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 2. 模型选型（盲评后标注：business）

- 题干：某教育科技公司要开发一个B端作文批改系统，客户要求两周内交付MVP，预算有限。系统需完成两类任务：一是给学生作文写鼓励性评语（简单创作），二是分析作文逻辑结构并给出改进建议（复杂推理）。请说明你会如何做模型选型，先做什么，产出什么，以及如何判断选型有效。
- 出处：写小说 续写 自定义创作   指令模型
        + 科学计算 推理逻辑     推理模型
- 参考答案：先拆任务：鼓励性评语用指令模型，追求快和便宜；逻辑分析用推理模型，追求准确。产出选型对照表并做小样本测试，对比两类模型在速度、成本、准确率上的表现。判断有效：评语任务响应快且成本低，分析任务准确率达标且客户可接受。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 3. 模型选型（盲评后标注：tradeoff）

- 题干：团队在为一个客服知识库项目选型：A方案全部用指令模型，响应快、成本低，但复杂问题回答准确性一般；B方案全部用推理模型，准确性高，但响应慢、成本高。客户对响应速度和准确性都有要求，预算中等。你会选哪个？放弃什么？什么条件下会反转？
- 出处：业务情况进行选型
- 参考答案：选A为主、B为辅的混合方案：简单问答走指令模型保速度和成本，复杂问题走推理模型保准确。放弃“全部用推理模型”的极致准确，也放弃“全部用指令模型”的极致低价。若客户对准确率要求极高且预算充足，或复杂问题占比很高，则反转为以推理模型为主。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 4. 模型选型（盲评后标注：cost_risk）

- 题干：一家B端客户要求你们在合同里承诺“所有回答准确率不低于95%”，并希望尽量用便宜的指令模型。请分析这里有哪些成本和风险，分别由谁承担，以及你会怎么兜底。
- 出处：速度快 但是准确性一般
- 参考答案：风险一：指令模型准确性一般，承诺95%可能达不到，导致违约赔偿，由乙方承担。风险二：为达标被迫换推理模型，成本上升，由乙方或转嫁客户。兜底：合同按任务分级承诺准确率，简单任务用指令模型，复杂任务用推理模型，并设置人工复核和免责条款。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 5. 模型选型（盲评后标注：synthesis）

- 题干：你是一家AI产品公司的产品负责人，客户是学校，要求三个月内交付一个作文辅导Agent，预算固定，且必须私有化部署。任务包括：生成鼓励评语（简单创作）、分析作文逻辑（复杂推理）、回答学生常识问题（简单问答）。请做模型选型决策，说明依据、边界和失败信号。
- 出处：指令模型
      + 无思考过程    速度快 但是准确性一般  适合较简单性任务
    + 推理模型
      + 有思考过程    速度慢 但是准确性较高   适合较复杂性任务
- 参考答案：决策：鼓励评语和常识问答用指令模型，逻辑分析用推理模型，混合部署。依据：简单任务优先快和便宜，复杂推理优先准确，预算和周期有限。边界：推理模型只用于逻辑分析，不扩散到简单任务。失败信号：评语响应慢或成本超支，逻辑分析准确率不达标，客户投诉。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 6. 文档分级与清洗（盲评后标注：concept）

- 题干：在汽车销售智能客服项目中，用户问题涉及闲聊、专业知识（word/pdf/新闻）和优惠保险等。如果不先做文档分级与清洗，直接全量解析入库，会对业务交付和客户体验造成什么具体问题？请结合材料说明。
- 出处：用户可能会问什么问题
- 参考答案：不先分级清洗，解析工具会把闲聊、新闻、优惠等不同质量与用途的内容混在一起，导致检索结果噪声大、客服回答不专业或答非所问，客户信任下降；同时团队要花大量时间事后修补，交付周期拉长，售后成本上升。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 7. 文档分级与清洗（盲评后标注：business）

- 题干：假设你负责一个汽车销售智能客服项目，客户提供了大量word、pdf和新闻稿。请说明你会如何安排文档分级与清洗的工作步骤，先做什么、产出什么，以及如何判断这一步做到位了。
- 出处：基于分类后的文件做处理
- 参考答案：先按来源和用途分级分类（如专业知识、优惠政策、闲聊素材），再对分类后的文档用解析工具自动化处理，最后按业务规则过滤清洗。产出是分级清单和清洗后的可用文档集。判断标准：客服回答专业问题准确率提升、无关内容明显减少、人工修补量下降。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 8. 文档分级与清洗（盲评后标注：tradeoff）

- 题干：项目周期紧张，团队有两种做法：A. 先快速全量解析入库，上线后再逐步清洗；B. 先花时间做文档分级与规则清洗，再上线。你会选哪个？放弃什么？什么条件下你会反转选择？
- 出处：基于分类后的数据进行自定义的规则过滤与清洗
- 参考答案：选B。放弃短期上线速度，换取客服回答质量和售后成本可控。若客户明确只要求演示原型、不考核回答准确率且周期极短，可先选A快速验证，但需约定后续清洗计划。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 9. 文档分级与清洗（盲评后标注：cost_risk）

- 题干：在文档分级与清洗环节，如果分级规则定得太粗或清洗过度，会带来哪些成本和风险？这些后果由谁承担？你会怎么兜底？请至少说出两项风险。
- 出处：利用解析工具进行自动化处理
- 参考答案：风险一：分级太粗导致噪声内容混入，客服回答不专业，客户流失，由客户和交付团队承担。风险二：清洗过度误删关键信息，回答缺失，售后投诉增加。兜底：建立抽样复核和客户确认机制，保留原始文档备份，上线后监控回答质量并快速回滚规则。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。

### 10. 文档分级与清洗（盲评后标注：synthesis）

- 题干：客户预算有限、要求两个月上线汽车销售智能客服，且明确考核回答准确率。文档来源杂、质量参差。请给出你的文档分级与清洗决策、依据和失败信号。
- 出处：如何去实现不是产品应该考虑的事情
- 参考答案：决策：优先对高频专业问题相关文档做精细分级和规则清洗，低频闲聊类暂缓。依据：预算和周期有限，必须把资源投在影响准确率的核心文档上。失败信号：上线后专业问题回答准确率不达标或人工修补量持续上升，说明分级清洗策略需调整。
- 盲评：题型对 / 理解 / 业务视角 / 可溯源。
