## 3. 发现

### 3.1 日期字段覆盖率为 0/15

5 次真实搜索共返回 15 条网页来源，`published_at` 全部为 `null`，落库与前端均显示「未标注日期」。`retrieved_at=2026-11-24` 正常。

结论：Tavily `basic` 对这批中文页面基本不回 `published_date`。日期机制本身工作，但对「最新」类问题几乎不提供时间信息；要提高时效可信度需换 `search_depth=advanced` 或改用有日期的来源，属于设计变更。

### 3.2 空结果分支未在真实环境触达

#6、#7 两次无意义查询，Tavily 都返回了结果并通过预过滤（`web_status=ok`），因此「材料里没有直接讲到，联网也没查到」的 `empty` 分支仍只有 fake 测试覆盖。用户结论里写的「查不到」来自模型判断，不是 `empty` 兜底文案。

### 3.3 预过滤被意图词污染（真实质量问题）

`query = 用户原文`，显式触发词「联网」本身参与「≥2 字词项重叠」判定，导致：

- #6 返回维基词典「不存在」、百度百科「没有」、腾讯云「搜索不出来」3 条无关链接；
- #7 返回机核「复刻 DeepSeek 联网搜索」、Chrome 帮助「搜索网络信息」、火山引擎「联网搜索路线图」3 条无关链接。

两条查询的网页来源全部与问题无关，但 `web_status=ok`，前端会照常展示这些链接。这是当前预过滤规则的结构性弱点：越明确地要求联网，越容易把「联网」相关文章拉进来。

### 3.4 相似度阈值偏松（#5）

纯乱码问题 `qzxvplorb` 命中了 2 条不相关材料，`is_grounded` 判为 true，因此没有触发联网（符合「本地 grounded 不联网」的规则）。材料出处与问题毫无关系，说明 `retrieval_min_cosine` 对这类输入偏松。现实影响是：真正超纲但embedding 偶然相似的问题，可能不联网。本次只观察到乱码输入，未观察到正常问题误判。

- smoke 期间未改动代码、spec 或前端文件；归档带来的 spec 同步不在本记录范围。

## 5. 结论

6.2 要求的四项（延迟、返回条数、日期字段、单次成本）已记录，4 条核心场景通过，任务可标记完成。

已知质量缺口（不阻塞归档，建议另开 change）：

1. 停用词/意图词处理：显式触发词不应参与词项重叠；或 query 去除「联网/查一下/最新」等触发词后再检索。
2. 无意义 query 应能落到 `empty`，而不是靠模型自觉说「查不到」。
3. 日期覆盖率低：评估 `search_depth=advanced` 或按来源域名补日期。
