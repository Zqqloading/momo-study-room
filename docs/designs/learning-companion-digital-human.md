## Problem Statement

自学 agent 理论时，能看懂单个名词，但串不成体系。行业黑话密集，身边没有能追问、能纠错、能记住进度的人。现有工具（搜索、聊天机器人、课程）不给"每天一小步 + 当场验收"的结构，导致看得多、讲不出、用不上。

目标：给自己造一个数字人伴侣。每天 20 分钟，围绕一个 agent 理论概念，要求用大白话讲解，再用五道自测题检验，分数与误解进入记忆，第二天按掌握度调整内容。

## What Makes This Cool

- 它拒绝说黑话。不问"你懂了吗"，只问"用你自己的话说一遍"。
- 每天 20 分钟一个概念，讲一遍加五道自测题，分数立刻出来。
- 它记得你的误解。同一个误解第三次出现时，它先问你上次那个坑。
- 它是个数字人。开源 3D 形象加语音输入，念题、追问、给反馈都用说的。
- 三个月后，你手里有一份自己的概念掌握档案和一套自测题库，可以讲给别人听。

## Constraints

- 学习时间每天 20 分钟，设计目标：20 分钟内能做完。计时器是建议值，不强制中断。
- 建设时间另计。排期门槛见 Open Question 3；20 分钟是使用时间，不是开发时间。
- 单用户：你本人为主，偶尔演示给别人。不做账号体系。演示数据固定在项目内 `data/demo/`；一键清空只删 `data/demo/` 下的数据库和缓存，不删 `materials/` 和 `concepts.yaml`；清空前二次确认。一个"档案" = 一个 SQLite 库 + 一份 `concepts.yaml` + 一个 `materials/` 目录。
- 权限边界：只读项目目录，只写自己的数据；不碰项目外文件，不操作电脑。
- Windows 本机（假设：可出声、有麦克风的桌面环境；若实际是手机或公共空间，语音降级为打字，形象可保留但非必需）。
- LLM 用 mimo-2.6，ASR 用 MiMo，TTS 用 breezeblue，评分用 DeepSeek Flash；托管方式见待定区，当前按云端 API 设计，失败时只显示文字。
- 项目直接放在当前根目录 `D:\football agent`，不新建 repo；`bff/`、`core/`、`web/`、`assets/`、`materials/`、`concepts.yaml`、`data/` 都在根目录下。
- BFF 独立：`bff/` 负责 WebSocket、静态资源、会话和外部 API 编排；`core/` 只做领域逻辑，需要模型时通过 BFF 的内部接口调用，不直接联网。
- 内容以你自己的学习材料为主，官方文档和论文只作种子补充。系统不生产原创课程，课程由材料抽取、排序而来。每个概念的 `plain_def` 和每道题都必须带 `source_url` 和 `source_excerpt`，v0 就开始记录，不等 v2。
- 3D 形象和语音输入是 demo 的交付项；口型精度待定（当前假设幅度驱动，音素级放最后）。
- 不做云端部署，不做账号体系。

## Premises

P1. 你不缺资料，缺的是把概念讲成人话的检验。伴侣的核心价值在追问和验收，不在讲得多好。（已确认）
P2. 20 分钟是设计目标：任务要能在 20 分钟内完成并看到结果；计时器不强制中断。（已确认）
P3'. 原前提"学习伴侣本身就是你要跑通的那个小 agent"已撤销。你要的是用数字人陪你学理论，不是靠造 agent 来学 agent，也不是从零编写课程内容。（2026-11-19 会话中途更正）
P4. 3D 形象是 demo 的交付项；口型精度待定，当前假设幅度驱动、音素级放最后。（2026-11-19 由"静态面孔"更正；2026-11-21 精度标为待定）
P5. 记忆是技术核心：概念掌握度 + 误解档案 + 错题回炉。（已确认）

## Approaches Considered

### Approach A: 终端教练

Python 单进程加 SQLite，每天从概念表挑一个，要求你用文字讲解，生成五道自测题并评分。Effort S，风险 Low。能最快跑通闭环，但没有陪伴感，不满足数字人形态。

### Approach B: 学习教练服务

FastAPI 服务加状态机、分层记忆、工具层（抓原文、检索）、Web 前端、TTS 与 3D 形象。Effort XL，风险 High。**用户选择此方案**，理由是要做对的东西，而不是先做一个粗糙的能用版本。

### Approach C: 语音优先仪式

不做屏幕，按键后它用固定声音念题，你口述讲解，它追问。Effort M，风险 Med。仪式感最强，但语音识别受口音和环境噪音影响，验收质量不稳。**明确推迟，不进本次三个月路线图**；若以后做，作为后续独立实验，不在当前路线图，不占用 20 分钟预算。

## Recommended Approach

架构按 B 走，交付按竖切。否则按待定区的每周建设时间，三个月会停在搭架子上。

输入方式：语音为主，打字兜底。语音是**半双工**：按住说话，松开后开始识别和回答；它说话时麦克风关闭，不能插话，说完你再按。这样不需要回声消除、VAD 和打断逻辑，20 分钟节奏可控。ASR 原文落 `asr_text`，术语纠错后的可编辑文本落 `explained_text`，同时记 `asr_confidence`；低置信度时才提示你改字。打字入口保留，用于安静环境或术语识别失败时的纠正。

### 数据模型

- concepts(id, mastery 0-5, status, prior_status, last_seen, review_started_at, review_due_at) 运行时表；内容字段不落库，读 `concepts.yaml`
- question_bank(id, concept_id, kind: recall|discriminate|apply, question_text, rubric_json, options_json 可空, answer_key 可空, source_url, source_excerpt)
- sessions(id, date, concept_id 可空（综合场、诊断与讲解为多概念）, kind: diagnostic|daily|synthesis|review, status: completed|partial|unscored, started_at, minutes, asr_text（原始转写）, explained_text（纠错后可编辑文本）, input_mode: voice|text, asr_confidence, session_score, created_at)
- session_concepts(session_id, concept_id) 综合场、诊断与跨概念讲解使用
- session_questions(id, session_id, concept_id 可空, question_bank_id 可空, question_role: new|review|misconception, kind, question_text, rubric_json, options_json, answer_key, answer_text, score 0-100 可空（未作答或未评分）, feedback, misconception_id, source_url, source_excerpt, created_at)
- misconceptions(id, concept_id, key, text, status: candidate|active|resolved, times_seen, clean_streak, last_seen)

`session_questions` 存每题的实际问法与你的原文回答，生成题也先落库再评分，保证可审计、可回炉。题目落库时从 `question_bank` 复制 `source_url` 与 `source_excerpt`；v2 的生成题在生成时一并写入出处与摘录，v0 就要写入 url 和摘录。

### 评分契约（v0 必须实现）

- 评分由 DeepSeek Flash 执行，返回 JSON：每题分数、一句为什么、至多一条会话级误解（每题只标是否命中，并带 `certain` 布尔）；解析失败重试一次，仍失败本次记 `status=unscored`，不写分数。（重试一次为假设）
- `question_role=new` 指新题，不指新概念；复讲场和诊断题也用 `new`。`kind=review` 讲解场：`explained_text` 非空记 `status=completed`，`session_score` 为空。
- 每题 0 到 100 分，五档 rubric：0 空白或"不知道"；40 提到正确名词但关系说错；70 方向对但含糊；90 正确且给出自己的例子；100 正确、举例且说出边界或反例。
- 一次会话总共五道题，按早期题（复习 + 误解，最多 2 道）分配：
  - 0 道早期：2 回忆 + 2 辨析 + 1 应用
  - 1 道复习：1 复习 + 1 回忆 + 2 辨析 + 1 应用
  - 1 道误解：1 误解 + 1 回忆 + 2 辨析 + 1 应用
  - 2 道复习：2 复习 + 1 回忆 + 1 辨析 + 1 应用
  - 1 复习 + 1 误解：1 复习 + 1 误解 + 1 回忆 + 1 辨析 + 1 应用

  每次结束前校验 `session_questions` 行数 = 5（诊断和 review 讲解场除外）。
- `session_score` = 已作答题目得分的算术平均；未作答的题不评分、不按 0 计。一题未答记 `status=unscored`，不写分数；少答但至少答了一题记 `status=partial`。
- 每个概念的 `concept_session_score` = 该概念当次会话里 `question_role=new` 的题得分均值；`review`/`misconception` 角色、诊断题、综合场不计入 mastery。
- `mastery` 0 到 5 = round(该概念最近三次 `concept_session_score` 的均值 / 20)，不足三次用已有的；新概念从 0 开始。
- 90 天验收的"均分 80"按每个概念最近一次 `concept_session_score` 求平均；分母只含至少有一次 daily 分数的概念，proposed/skipped/orphaned 和没有分数的 known 不计入。
- 验收卡逐题显示分数，不只给总分；未评分题显示"未作答"。
- 摸底场（`kind=diagnostic`）不受五题规则限制：从 active 概念里每个抽 1 题，最多 10 题；active 不足 10 个时按实际数量出题。每个概念的初始 `mastery` = round(该概念那道题的得分 / 20)，没抽到的从 0 开始。摸底不计入最近 30 天完成数，摸底错题不进复习队列。（此映射为假设，摸底跑一次后再校准）
- 辨析题按 `answer_key` 确定性判分，不进 LLM 评分；rubric 只用于开放题。

### 误解生命周期（v2 实现，v0 只落库）

- 阶段：v0 只在评分时写入 `misconceptions`（status=candidate），不主动重问；v2 起做提升、重问和解决。
- 提取：每次会话由评分模型从讲解与错题中最多提取 1 条误解，归一到 (concept_id, key)。综合场的误解归属到暴露它的那道题的 `concept_id`；模型无法归属时不建 active 记录，按 candidate 记在该场第一个概念下，且不触发重问。
- 提升：同 (concept_id, key) 第二次被确定检出时，candidate 升为 active，`times_seen` 从 2 起算；模型不确定仍写 candidate，不计数。
- 触发：active 且 `times_seen >= 3`（第三次出现）时，下一次会话开头先问这条。
- 解决：只在 `status=active` 时检查，且跳过提取/检出该误解的那次会话。会话结束时：当次没有带该 `misconception_id` 的题 → `clean_streak` 加 1；有且得分 >= 80 → 加 1，否则清零。`clean_streak >= 2` 置 resolved。
- 提升时 `clean_streak=0`；重开时 `clean_streak=0`；candidate 不能直接 resolved。
- 重开：resolved 再次被确定检出时，状态回到 active，`times_seen` 继续加。

### 错题与间隔复习

- 错题（用于详情展示）= 某题得分 < 60，或回答为"不知道"。
- 待巩固（用于详情展示）= 某题得分 60 到 79。
- 复习队列的唯一真相源是 `concepts.review_due_at`：非空即在队列。日常会话结束后，该概念 `concept_session_score < 80` 且 `review_due_at` 为空 → 设为次日，并记 `review_started_at=today`；`>= 80` → 清空两者。
- 复习结果 = 该概念当次会话里 `question_role=review` 的题的得分均值；0 条复习题时无结果、不改 due。
- 详情：错题展开后显示当时的题目、`asr_text`（原始转写）、`explained_text`（纠错后文本）、得分和反馈。
- 间隔：复习结果 < 60 → 次日；60 到 79 → 3 天后；>= 80 → 清空 `review_due_at` 和 `review_started_at`。距 `review_started_at` 满 14 天仍 < 80 就按 14 天循环。v1 只做次日重问，v2 上线完整间隔表。
- 同场既复讲又复习同一概念时，复习结果优先决定 due；日常分数只在当次没有复习题时用于入队。
- 到期判定：`review_due_at <= today` 即到期；队列 = 非空，到期项优先。
- 时间：复习占用当天 20 分钟内的前 4 分钟，最多 2 题，计入当天五道题；优先级为未解误解 > 到期复习 > 新概念。
- 错过：`review_due_at` 不变，只显示"逾期"；逾期项优先于新概念，不延长当天时长。
- 归档：档案页分"错题（<60）"和"待巩固（60-79）"两栏。

### 概念连接（解决"串不成体系"）

- Planner 只在前置概念的 `mastery >= 3` 或状态为 `skipped` 时才引入新概念。
- 每第 7 次完成的日常会话是综合场，20 分钟内：5 道综合题连接 2 到 3 个概念（约 15 分钟）+ 5 分钟跨概念讲解。综合场只记录 `session_score`，不更新任何单概念的 mastery。
- 跨概念讲解记一条 `kind=review` 的会话，`session_concepts` 存至少 3 个概念，`explained_text` 存转写；不参与 mastery，不计入 30 天完成数；当天只算综合场一次。
- 每第 4 次日常会话是复讲场：重选一个 `concept_session_score < 80` 或最久没见的概念，按 daily 计分并更新 mastery，占一个日常名额。与第 7 次综合场同日时优先综合场，复讲顺延。
- 账：90 天按 24/30 约 72 次完成，其中约 10 次综合场，剩约 62 次日常；每第 4 次复讲给约 15 次复讲，不够 1.5 次/概念时，把额外的日常会话改成复讲。
- 验收项：90 天内完成一次连接至少 3 个概念的 5 分钟讲解，以这条 review 会话为证据。

### 每日闭环（20 分钟，语音为主）

有到期复习或误解触发时，前 4 分钟先复习：

1. 0-4 分钟（当有到期复习，或 v2 起有未解误解触发时）：先问复习题或上次的误解，作答后立即给分，最多 2 题，计入当天的五道题（误解重问占其中一个名额）。
2. 4-5 分钟：它念今天的题目（例：用你自己的话说说 agent 和 workflow 的区别）。
3. 5-9 分钟：你按住说话讲解，转写出来后可以先改错字。
4. 9-17 分钟：当天剩下的新概念题逐题出现，按评分契约的配比补足五道，每题可点"不知道"，逐题落库。
5. 17-19 分钟：逐题给分，指出一个具体误解，给一句为什么。
6. 19-20 分钟：更新掌握度、错题队列、下次复习日期和误解档案，预告明天。本次写 `sessions`、`session_questions`、`concepts.mastery/status/last_seen/review_due_at`、`misconceptions`，不生成学习日志。

没有到期复习时：0-1 分钟念题，1-6 分钟讲解，6-14 分钟五道新概念题（2 回忆、2 辨析、1 应用），14-19 分钟评分，19-20 分钟更新。

计时器是**建议值，不强制中断**：到 20:00 只提示"可以收尾"，不自动提交；你点"结束本次"才按已答题目评分。一题未答记 `status=unscored`，不写分数；少答但至少答了一题记 `status=partial`。跨概念的"串起来"由第 7 次综合场承担，不塞进每天。

### 界面结构（未出图）

六屏，无导航栏：
0. 复习（仅当有到期复习或未解误解触发）：复用追问屏，逐题显示，最多 2 题。
1. 今日任务：题目、按住说话按钮、转写预览、20 分钟计时。
2. 追问：每次一题，按住说话或点选项，另有"不知道"按钮。
3. 验收卡：逐题得分、一句为什么、一个误解、档案入口链接。
4. 档案：概念掌握度、最近 30 天完成数、错题与待巩固两栏、误解列表。
5. 综合场（每第 7 次完成的日常会话）：5 道综合题 + 5 分钟跨概念讲解录制。

3D 形象常驻在 1、2、3 三屏的左侧，v1 交付时一并出现。它说话时"按住说话"按钮禁用，避免半双工下误录。

### 分阶段交付

四个阶段合计 40 到 56 小时。按待定区当前占位，全部跑完需要 13 到 28 周；三个月（最多 36 小时）覆盖 d0 + v0，周投入 3 小时时还能覆盖 v1 的下限。以下小时数已包含 20% 缓冲。

- d0（阶段 1，8 到 12 小时）：先 d0a 连通性（2 到 3 小时，验四个 API），再 d0b 形象与音频（6 到 9 小时，VRM、半双工语音、MiMo ASR、mimo-2.6、breezeblue、幅度驱动口型）。只跑一次完整对话，不接知识库，不写数据库。
- v0（阶段 2，8 到 12 小时）：教练内核。最小概念确认页、起步材料与起步节点数见待定区、10 题摸底 + 每概念 5 道预写题、语音讲解转写、DeepSeek Flash 评分、掌握度落库。
- v1（阶段 3，12 到 16 小时）：Markdown/HTML 自动解析、父子切块入库与抽题、概念按材料扩到待定区的中间目标、次日重问、Web 单页整合 TTS 与形象。
- v2（阶段 4，12 到 16 小时）：PDF 解析、材料增量更新自动化、概念扩到待定区目标节点数、完整间隔复习、误解重问、第 7 次综合场；音素级口型可选，不做预生成视频。

### 题目来源

- v0：从起步材料里人工抽取概念与题目（数量见待定区，可以在会话里让模型抽、你确认），题库全部预写：10 道摸底 + 每概念 5 道；每题带 rubric、答案键和出处摘录，辨析题带可选项和 `answer_key`。
- v1：Markdown/HTML 材料自动解析与抽题，生成题先写入 `session_questions` 再评分；当天题目由 Windows 计划任务在前一晚预生成，写入 `question_cache` 表；没有缓存时打开先同步生成，超 30 秒退回旧题。
- v2：加 PDF；材料增量更新时只对新增或变更的块抽概念；概念数按材料覆盖自然增长，覆盖到待定区里的目标节点数。
- 兜底：生成失败或超时，退回题库里同概念的最后一道旧题，不阻塞当天会话。

## 知识库构建与全流程

知识库不是我去选一套课程，而是你把学过的材料放进来，系统从材料里抽概念、排顺序、出题考你。

### 材料怎么进来

- 支持格式：v0 收 Markdown 和 HTML；v2 加 PDF。HTML 只取正文，去掉脚本、导航和样式。
- 放置方式：仓库根目录 `materials/`，一个文件一份材料，文件名就是标题。
- 元数据：Markdown 用 YAML front matter 写 `source_url` 和 `tags`；HTML 从 `<title>` 和 `<link rel=canonical>` 取，取不到就留空。
- 规模：数量见待定区。
- 变更检测：按文件内容哈希判断，内容变了 `materials.version` 加 1，旧版本块保留，检索只用最新版本。

### 切块与抽概念

1. 切块用父子索引：父块按标题层级切，600 到 1000 token；父块内再按段落切子块，150 到 250 token，子块记录 `parent_id`。子块之间重叠 10%，父块之间不重叠。
2. 抽概念用父块，每父块最多 3 个概念。字段是 `name, aliases, plain_def, prerequisites, source_url, source_excerpt, difficulty 1-3`。
3. 检索用子块召回，命中后回溯父块，把父块全文交给模型；引用摘录取自子块定位。
4. 质量门槛：`plain_def` 不超过 60 字、必须是大白话，出现"本段介绍了""本文主要讲"直接丢弃；没有可引用摘录的丢弃；名字不是术语的丢弃。
5. 去重合并：名称归一化加别名，语义相似度大于 0.9 直接合并；0.75 到 0.9 进待确认，不自动合并。一个概念可挂多份材料，主出处只留一条。
6. 边界处理：父块超过 1000 token 就按小标题再切；子块少于 80 token 合并到相邻子块。token 数以所用模型的分词器为准，拿不到就用 tiktoken 近似。

### 概念确认页

- 一张表，每行：名字、60 字定义、出处、前置、难度、三个按钮"要学 / 已掌握 / 不学"。
- 批量操作：全选要学、按难度筛选、只看无前置的概念。
- 首次只确认起步节点数（见待定区），不要一次确认一百个；确认完就能开始第一天。
- "已掌握"直接把 `mastery` 记 5，状态 `known`，不进队列；"不学"状态 `skipped`，永久跳过；"要学"状态 `active`。
- 确认结果写 SQLite 的 `concepts.status`，不回写 YAML；YAML 后续改动不影响已确认状态。

### 概念地图（YAML）

- 概念地图是一个人可以读、可以手改的 YAML 文件：`concepts.yaml`，起步节点数见待定区，每个节点带前置。
- 结构：

```yaml
version: 1
concepts:
  - id: agent
    name: Agent
    aliases: [智能体]
    plain_def: 能自己决定下一步做什么的程序
    difficulty: 1
    prerequisites: []
    source:
      material: materials/agent-basics.md
      url: https://example.com/agent-basics
      excerpt: Agent 是能感知环境并自主采取行动的系统。
  - id: tool-calling
    name: 工具调用
    aliases: [function calling, 函数调用]
    plain_def: 让模型调用外部工具拿到结果再继续想
    difficulty: 2
    prerequisites: [agent]
    source:
      material: materials/agent-basics.md
      url: https://example.com/agent-basics
      excerpt: 模型通过工具描述决定何时调用哪个函数。
```

- YAML 是概念内容的唯一真相源；SQLite 只存运行时状态（mastery/status/last_seen/review_due_at）和会话分数，按 `concept.id` 关联。
- 确认页写 SQLite 的 `concepts.status`，不回写 YAML；YAML 同步在应用启动和文件变更时触发，只更新内容，不动 status；id 从 YAML 消失 → `prior_status` 记原状态、status 置 `orphaned`；id 回来 → 恢复 `prior_status` 并清空它。
- 跳过（skipped）视为已满足前置，后继照常解锁；确认页提示该操作会让哪些后继解锁。
- 载入时校验：id 唯一、前置存在、无环、每个节点有 `plain_def`、`source.url` 和 `source.excerpt`。任一失败就报错并指出坏节点，不自动修复。
- 起步与目标节点数见待定区；加节点只改 YAML，不重建数据库。
- Planner 只在前置概念 `mastery >= 3` 或状态 `skipped` 时解锁。
- 改图走 YAML；界面上的可视化编辑放 v2。

### 出题质量门槛

- 每题必须带 `source_excerpt` 和 rubric；指不到摘录就不出题。
- 辨析题的三个干扰项必须来自常见误解或相邻概念，不能随机拼。
- 首批生成后抽查 10 道，每晚生成后抽查 2 道（或全部 5 道）；不合格的重生成或手改，题目修订不影响已有分数。
- 抽查算内容时间：首批约 10 分钟、每晚约 2 分钟，不从 20 分钟里扣；跳过就用旧题，不阻塞会话。

### 每日选择顺序

- 候选池：`active` 且前置全部达标的概念。
- 优先级：未解误解（v2）> 到期复习 > 新概念。
- 新概念排序：难度低的先来，同级按材料新近度，再按最久没见。
- 每天只出一个新概念；复习最多 2 题，占当天五道题的名额。

### 材料更新

- 与"新增材料"同一流程：只对变更块重新抽取；新增概念进 `proposed`，等你确认。
- 已有概念只更新出处和摘录，**不重置 mastery**。
- 材料删掉后：同步时对比 materials 表与文件系统，文件消失 → 其概念记 `prior_status` 并置 `orphaned`，保留 mastery 和历史；文件回来 → 恢复 `prior_status`。月度复盘时提示。
- 同名概念相似度低于 0.75 视为两个概念，新概念进待确认。
- 不做摸底、不重置节奏；增量不触发完整初始化。增量流程从 v0 起就要能手工跑，v2 只是自动化。

### 语音与术语

- 转写后用概念名和别名做一次术语纠错（模糊匹配替换）；MiMo 若支持热词，再在识别阶段加。
- 转写结果随时可改错字；`asr_confidence` 低于 0.6（假设阈值）时提示"建议改字"。

### 数据模型补充

- materials(id, title, path, format, content_hash, version, added_at, status, source_url, tags)
- material_chunks(id, material_id, material_version, parent_id 可空, level: parent|child, heading_path, text, token_count, source_url)
- concept_sources(concept_id, chunk_id, excerpt, is_primary)
- concepts 运行时字段：mastery、status（proposed|active|known|skipped|orphaned）、prior_status、last_seen、review_started_at、review_due_at；内容字段以 YAML 为准
- question_cache(concept_id, target_date, question_json, created_at) 预生成题缓存

### 规划逻辑（"根据我的材料规划"）

- 只从 active 概念里选，且前置概念的 `mastery >= 3` 或状态 `skipped` 才解锁。
- 顺序优先级：未解误解 > 到期复习 > 新概念。
- 每天只出一个新概念，复习最多 2 题，总量不超 20 分钟。
- 每道题必须能指到至少一条 `concept_sources`；指不到就不出题，防止模型自由发挥。
- 材料覆盖缺口每月统计一次：哪些材料还没被抽成概念，哪些概念只剩一条出处。

### 全流程

首次初始化（每个档案只做一次，30 到 60 分钟，不计入每天 20 分钟）：
1. 你把第一批材料（数量见待定区）放进 `materials/`。
2. 跑一次抽取，得到候选概念清单。
3. 你逐条确认要学、已掌握、不学。
4. 从 active 概念里抽 10 个做摸底，每个 1 题；按得分校准初始 mastery（见评分契约）。
5. 系统生成第一批题目，你抽查 10 道，不合格的重写或删掉。
6. 设定节奏：每天 20 分钟，最近 30 天至少 24 次。

摸底记为 `kind=diagnostic`，不计入 30 天完成数。

新增材料（增量，不重做初始化）：
1. 把新材料放进 `materials/`，只对新增或变更的块抽概念。
2. 新概念进 `proposed`，你逐条确认要学、已掌握、不学。
3. 只给新概念出题，你抽查 10% 或 10 道。
4. 不做摸底，不重置节奏，不重置已有 mastery；新概念从 0 开始，标"已掌握"的记 5。

网络种子材料不走单独流程：无论来自网页还是本地，都按上面两条走。第一次那批算初始化，之后每批都算增量。

每天（20 分钟）：复习 → 今日概念 → 讲解 → 五问 → 评分 → 更新记忆。

每第 7 次完成的日常会话（约 9 天）：综合场，连接 2 到 3 个概念，不收新材料、不加时长。

每月复盘（额外 20 分钟，不占每天预算）：只读档案和统计，不记会话、不算 24/30；看掌握度分布、误解清单、材料覆盖缺口，决定下个月加哪些材料、哪些概念要重出题。

材料更新时：增量抽取 → 候选概念 → 你确认 → 新概念入队；已有概念只更新出处，不重置 mastery。

### 谁做什么

- 你：选材料、确认概念、抽查题目、每天讲解与作答。
- 模型：抽概念、写 `plain_def` 初稿、出题、评分、提取误解。
- 系统：排期、状态、复习、统计。

### 失败与降级

- 解析失败：不支持格式、文件损坏、空文件、编码错误 → 记录原因、跳过该文件、提示换格式；不影响同批其他文件。整批 0 份可用时，初始化暂停并提示。
- 抽取质量差：`plain_def` 出现套话或超过 60 字就丢弃；整份材料合格概念少于 3 个时，跳过该材料并提示你换格式。
- 概念太碎：同一块最多保留 3 个，多出的合并同级概念。
- 题目找不到出处：不出题，退回该概念已有的旧题。
- 增量冲突：同名低相似度进待确认，不自动合并，避免污染已有掌握度。
- 语音转写错：转写后用概念名和别名做术语纠错；仍错就在评分前改字，`asr_confidence` 低时给出提示。

## Open Questions

1. DeepSeek Flash 的评分稳定性：先用 20 条人工评分对照，一致率低于 75% 就换提示词或加二次校验。
2. 第一批具体放哪几份材料（数量见待定区）；概念由你逐条勾确认，模型只做提名。
3. 每周建设时间能否稳定在 2 到 3 小时。这一条不确认，三个月排期不成立。
4. 口型做到什么程度：幅度驱动够不够，什么时候上音素级。ASR 已定 MiMo；术语准确率按 80% 实测，短答延迟按 2.5 秒目标实测，讲解转写另计。
5. 父子索引的召回方式：关键词（FTS5）与向量混合；embedding 模型见待定区，语义去重已经依赖它。
6. 各 API 的准确接口见待定区；拿到后先做连通性和延迟实测，再写进 d0。

## Success Criteria

- 90 天内完成待定区里的目标节点数。目标只统计 `active` + `known`；`skipped`/`orphaned` 从分母里扣除，确认页显示"跳过/已掌握后目标变为 N"。"完成一个概念" = `known` 直接算完成，或 `active` 至少一次 daily 的 `concept_session_score` >= 80。
- 3 分钟连贯讲解是能力标准：每周从日常讲解录音里抽 1 个概念验证 >=3 分钟（日常讲解本身 4-5 分钟，不需要额外时段）；每第 7 次综合场完成一次连接至少 3 个概念的 5 分钟讲解并留下 review 会话。
- 最近 30 天完成至少 24 次会话。"完成一次会话" = kind 为 daily/synthesis 且至少 3 道题已评分；partial 少于此不计，diagnostic 和 review 讲解场不计入。
- 从打开到拿到今日任务少于 30 秒，评分反馈少于 10 秒；评分延迟以校准阶段的实测为准。
- demo 阶段：短答（录音不超过 10 秒）从松开按钮到第一帧音频 ≤2.5 秒。预算：ASR 0.6s、LLM 首 token 0.8s、TTS 首音频 0.7s、网络抖动 0.2s（合计 2.3s，留 0.2s 余量）。讲解（4-5 分钟）不适用这个预算，单独要求转写在录音结束后 60 秒内就绪。mimo-2.6 和 breezeblue 必须支持流式；不支持则短答目标改为 4 秒，登记到待定区。
- 语音验收：20 句术语测试里，目标术语被正确转写的比例不低于 80%；逐字匹配，同义替换不算对；2.5 秒单独测。接口实测前，2.5 秒和 80% 是目标不是承诺。
